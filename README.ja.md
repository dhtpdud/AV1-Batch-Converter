# AV1 Batch Converter

[English](README.md) | [한국어](README.ko.md) | [简体中文](README.zh-CN.md) | **日本語** | [Español](README.es.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Português](README.pt-BR.md) | [Русский](README.ru.md) | [العربية](README.ar.md) | [हिन्दी](README.hi.md)

フォルダーとそのサブフォルダー内のすべての動画を AV1 に変換する Windows バッチスクリプトです。
まず NVIDIA NVENC を使い、NVENC が使えない場合は別のエンコーダーに自動で切り替えます。

> [!WARNING]
> **変換結果に字幕トラックは残りません**。Y モード（元のファイルを削除）では、元のファイルの字幕もファイルとともに失われ、復元できません。
> まず N モードを使い、結果を確認してから Y モードを使ってください。最初に[制限事項](#制限事項)をお読みください。

## 想定される結果

スクリプトを実行すると、次のようになります。

- フォルダーとそのサブフォルダー内の mp4、mkv、mov、avi、wmv、flv、webm、m4v、ts、mts、m2ts、mpg、mpeg ファイルを検索します。
- すでに AV1 の動画は変換しません。
- 長さが1分以上の動画は、まず中央の10秒をエンコードします。推定サイズが元のファイルの 90% を超える場合、その動画は変換しません。
- 完成した結果が元のファイルと同じサイズかそれより大きい場合、結果は破棄し、元のファイルを残します。
- 変換に失敗した場合、元のファイルは削除しません。
- AV1 の確認とエンコードは同時に進みます。エンコードは一度に1ファイルずつ処理します。
- もう一度実行すると処理済みのファイルはスキップされるので、途中で止めても続きから再開できます。

**すべての動画が小さくなるわけではありません**。すでに十分圧縮された動画はスキップされ、削減量は動画ごとに異なります。

### どれくらい小さくなるか

**0%（変換せず、元のファイルを保持）から、実測の最大 96% まで**。同じサイズかそれより大きい結果は破棄されるため、ファイルが大きくなることはありません。

これらの結果は、1台の PC からランダムに選んだ実際の動画52本を、デフォルト設定（NVENC、CQ 30）で測定したものです。

| ケース | 元のファイルに対するサイズ | 削減率 |
|---|---|---|
| 最大の削減 | 4% | 96% |
| 変換された41本の中央値 | 44% | 56% |
| 変換された動画の中で最小の削減 | 89% | 11% |
| スキップされた11本（推定サイズ 96-233%） | 100%（元のファイルを保持） | 0% |

| 元のコーデック | サンプル数 | 変換数 | 変換された動画の元のファイルに対するサイズ |
|---|---|---|---|
| H.264 | 25 | 18 | 4-89% |
| HEVC | 25 | 21 | 15-88% |
| VP9、MPEG-4 | 各1 | 2 | 81%、23% |

元のビットレートが高いほど、削減量も大きくなります。スキップされた動画も含めたサイズの中央値は、5 Mbps 未満で 76%、5-15 Mbps で 50%、15-40 Mbps で 27% でした。

これらの数値は保証ではありません。

- 各動画は映像トラックのみを、25%、50%、75% の各地点から10秒ずつ、合計30秒使って比較しました。ファイル全体を変換した結果ではありません。
- 音声は通常そのままコピーされるため、実際のファイルの縮小幅はこれらの数値より小さくなります。
- 測定したのは長さ1分以上の動画のみで、1人のコレクションです。他の動画では範囲が異なる場合があります。
- 測定したのは NVENC のみです。他のエンコーダーや他の `CQ` 値では結果が異なります。
- 変換前の推定が外れると、削減が 10% 未満の結果が残ることがあります。

### 結果の保存先

| モード | 保存先 | 元のファイル |
|---|---|---|
| N（推奨） | 各フォルダー内の `av1\` フォルダー | 保持 |
| Y | 元のファイルがあった場所 | 変換に成功すると**完全に削除**（ごみ箱には移動しません） |

拡張子は元のファイルと同じです。例外は mov、m4v、ts、mts、m2ts、mpg、mpeg で、これらは AV1 を格納できないため `.mp4` として保存されます。

### 変換後に保持されるもの

以下の結果はテスト動画で確認しました。

| 項目 | 結果 |
|---|---|
| 最初の映像トラック | AV1 に変換 |
| 音声トラック（複数トラックと言語タグを含む） | 保持。そのままコピーします。mp4 に保存する場合、互換性のない形式は AAC 192 kbps に変換します |
| チャプター、タイトル | 保持 |
| 10-bit | 保持 |
| HDR10（BT.2020、PQ、マスタリング ディスプレイ メタデータ） | 保持（NVENC で確認済み） |
| 回転 | 映像そのものを回転させて保存します。見た目は同じです |
| **字幕トラック** | **失われます** |
| **2番目以降の映像トラック** | **失われます** |
| **4:2:2 と 4:4:4 の色** | **4:2:0 に下がります** |

## 動作要件

- Windows 10 または 11
- PATH 上に `ffmpeg` と `ffprobe` があること
- 下記のエンコーダーのうち少なくとも1つ

| 順序 | エンコーダー | 必要なもの |
|---|---|---|
| 1 | NVENC（`av1_nvenc`）、2エンジン | AV1 エンコーダーを2基搭載した NVIDIA グラフィックスカード（RTX 4070 Ti など） |
| 2 | NVENC（`av1_nvenc`）、1エンジン | AV1 対応の NVIDIA グラフィックスカード（RTX 40 シリーズ以降） |
| 3 | Intel Quick Sync（`av1_qsv`） | AV1 エンコード対応の Intel グラフィックス |
| 4 | AMD AMF（`av1_amf`） | AV1 エンコード対応の AMD グラフィックス |
| 5 | CPU（`libsvtav1`、preset 10） | SVT-AV1 を含む ffmpeg ビルド |

起動時に、スクリプトはこの順序で実際にテストエンコードを行い、最初に動作したものを使います。使用中のエンコーダーは `Encoder: ...` の行に表示されます。

## 使い方

1. [Releases](../../releases/latest) から `convert_av1.bat` をダウンロードします。
2. 変換するフォルダーを bat ファイルにドラッグするか、bat ファイルを実行してフォルダーのパスを入力します。
3. 対象フォルダーを確認し、`Y`（元のファイルを削除）または `N`（元のファイルを保持）を選びます。

確認の進行状況はウィンドウのタイトルに表示されます。別々のフォルダーに対して複数のウィンドウで同時に実行できますが、各ウィンドウの処理は遅くなります。

**停止するには**：ウィンドウを閉じます。変換中の `name.part.ext` ファイルが残るので、自分で削除してください。

### 設定

bat ファイルの先頭付近にある次の値を変更します。

| 値 | デフォルト | 意味 |
|---|---|---|
| `CQ` | 30 | 品質（0-63）。低いほど高画質でファイルは大きくなります。すべての動画に同じ値が適用されます |
| `JOBS` | 8 | AV1 かどうかを同時に確認するファイル数 |
| `MIN_SAVE` | 10 | 推定削減率（%）がこの値を下回る場合は変換しません |

## 測定結果

RTX 4070 Ti、i7-13700KF、Windows 11、2026-10 の ffmpeg ビルドで測定しました。他の環境では結果が異なります。

### エンコード速度

| 解像度 | NVENC、1エンジン | NVENC、2エンジン | CPU SVT-AV1 preset 10 |
|---|---|---|---|
| 8K (7680×3840) | 31 fps | 55 fps | 約 14 fps |
| 4K | 107 fps | 189 fps | 未測定 |
| 1080p | 400 fps | 574 fps | 約 518 fps |

CPU の測定は、他の変換を実行している間に行いました。1080p で比較したソフトウェアエンコーダー：SVT-AV1 約 518 fps、libaom 約 173 fps、rav1e 約 5 fps。

### CQ とファイルサイズ

8K HEVC 動画（元は 30 Mbps）の20秒分を NVENC で変換した結果です。すでに十分圧縮された動画が CQ 30 で大きくなってしまう例です。

| CQ | ビットレート | SSIM（元のファイルとの比較） | 判定 |
|---|---|---|---|
| 30 | 53.9 Mbps | 0.9955 | 大きくなるためスキップ |
| 36 | 28.8 Mbps | 0.9936 | 削減量が小さいためスキップ |
| 42 | 14.3 Mbps | 0.9900 | 変換 |

このような動画を小さくするには `CQ` を上げる必要があり、そうすると他のすべての動画の品質も下がります。

### 大量のファイル

| 項目 | 結果 |
|---|---|
| ローカル SSD 上の動画23,100本の検索 | 0.6秒 |
| rclone crypt マウント上の動画22,887本の検索 | 8.9秒 |
| ローカル SSD 上の23,100本すべての処理（すべてすでに AV1） | 224秒 |

## 制限事項

### データ損失のリスク

- **字幕トラックは失われます**。2番目以降の映像トラックも同様です。これらが必要なファイルには Y モードを使わないでください。
- **Y モードの削除は元に戻せません**。`del` を使うため、ごみ箱には何も移動しません。
- **結果は再生して確認されません**。成否は ffmpeg の終了コードとファイルサイズだけで判定します。動画が壊れていても ffmpeg が成功と報告すれば、Y モードでは元のファイルが削除されます。
- **AV1 変換は非可逆です**。すでに圧縮された動画を圧縮しても、画質が元より良くなることは決してありません。
- **4:2:2 と 4:4:4 の動画は、4:2:0 に下げると色解像度が失われます**。編集やカラーグレーディングを予定している映像には N モードを使ってください。

### 判定が誤る可能性がある場面

- **推定は中央の10秒しか見ません**。テストでは、30% と推定された動画が実際には 45% になりました。小さくなるはずの動画がスキップされることがあります。
- **1分未満の動画は事前に確認されません**。サイズは変換後にのみ比較されます。
- **ffprobe がファイルを読み取れない場合、AV1 ではないものとして扱われます**。すでに AV1 のファイルが再度エンコードされることがあります。

### 再生と互換性

- 古いデバイスやプレーヤーでは AV1 を再生できません。
- avi、wmv、flv は拡張子を維持しますが、これらの形式の AV1 は標準的な組み合わせではなく、多くのプレーヤーでは再生できません。

### ファイル名とフォルダー

- `a.mov` と `a.mp4` のように結果の名前が重なる場合、後から処理されるファイルはスキップされます。
- 停止後に残った `name.part.mp4` は、次回の実行で通常の動画として扱われます。自分で削除してください。
- ジャンクションとシンボリックリンクのフォルダーは検索されません。

### 環境

- **画面のメッセージは英語です**。
- **韓国語版 Windows 11 でしかテストしていません**。bat ファイルは ASCII 文字のみを使うため、システムの言語には依存しません。コンソールのコードページ 437、949、65001 で動作することを確認しましたが、他の言語の Windows では実行していません。
- **実行中のウィンドウが使っている bat ファイルを上書きしないでください**。cmd はファイルを少しずつ読み込むため、実行中のウィンドウが誤った行を実行することがあります。
- CPU エンコードはかなり遅く、8K で約 14 fps です。
- ffmpeg に `libsvtav1` が含まれていない場合、スクリプトは CPU に切り替えられず、エラーで終了します。

### rclone マウントで使う場合

- `--vfs-cache-mode writes` が必須です。`off` では mp4 と mkv を書き込めず、すべてのファイルが失敗します。
- Y モードでは、**アップロードが完了する前に元のファイルが削除されます**。アップロードに失敗した場合はキャッシュに残ったコピーだけが頼りになるので、注意してください。
- アップロード中のファイルは、`--vfs-cache-max-age` と `--vfs-cache-max-size` を超えてもキャッシュから削除されないため、キャッシュのドライブには空き容量が必要です。
- これらの点はローカルの crypt リモートでテストしました。現在のバージョンは、実際のマウントではファイルの検索までしか確認しておらず、クラウドストレージではテストしていません。

### 未テスト

- **Intel QSV と AMD AMF での実際のエンコードは試していません**。該当するハードウェアがなかったため、オプションの解析のみ確認しました。品質が NVENC の CQ と一致するかどうかも不明です。
- NVENC エンジンが1基だけのグラフィックスカード（2エンジンモードの失敗をシミュレートして、切り替えのみ確認）
- NVENC のない環境は、グラフィックスカードを隠してシミュレートしました。実際の AMD や Intel の PC では実行していません。
- VR（球面）メタデータと Dolby Vision が保持されるかどうか
- CPU エンコードで HDR データが保持されるかどうか
- 260文字を超えるパス
